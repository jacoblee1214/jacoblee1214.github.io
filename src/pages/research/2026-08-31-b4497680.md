# iCloud Drive 안에 git 저장소를 둬도 되는가, 그리고 회피법은 실제로 듣는가

> **한 줄 결론**
> **조건부** — 노트 파일만 iCloud 에 두고 버전 기록 도구(git)의 관리 폴더는 iCloud 밖으로 빼서 맥 한 대에서만 돌리면 쓸 수 있고, 관리 폴더까지 iCloud 안에 둔 채 여러 기기에서 돌리면 안 된다 [1][2][3] — 확신도 **중간** (재확인 통과 2/3 · 비판자: 구현 관점의 위험 추론과 Git 분리 방법 설명은 상당 부분 타당하지만, 조사 주제의 핵심인 실제 손상 사례와 Obsidian Git의 알려진 문제가 거의 조사되지 않았다.)

## 1. 요약

- iCloud 는 파일을 하나씩 따로 올리고 내리므로, 저장소의 파일들이 같은 시점의 한 묶음으로 다른 기기에 닿는다는 보장이 없다 [1][3][4]
- 맥의 저장 공간 자동 비우기 설정은 로컬 사본을 지웠다 되살리는 범위만 다루고, 기기 간 변경 순서나 묶음 전달과는 무관하다 [5][6]
- 관리 폴더를 밖으로 빼는 방식은 버전 기록 도구가 지원하지만 다른 기기에는 그 경로가 없어 깨지고, 손상 사례와 Obsidian Git 쪽 공식 경고는 확인되지 않았다 [2][7][8]

## 3. 확인된 근거

## 4. 엇갈리는 점

- 반대편은 자동 비우기를 끄고 한 번에 한 기기만 쓰며 원격에 자주 올리면 위험이 없고, 깨져도 다시 받아오면 될 가벼운 사고라고 본다 [10][11]
- 비판자는 그 주장에 사례 목록·기간·구성이 없고, 기기 안의 안전만으로 기기 사이의 일관성을 추론했다고 짚는다 [10][11]
- 비판자는 다시 받아오기가 안 올린 작업·임시 보관분·로컬 설정을 빼놓는다고 짚고, 제외 표시를 붙이면 안전하다는 단정도 근거가 없다고 본다 [12][13]

## 5. 아직 모르는 것

- 저장소가 깨진 사례를 날짜·운영체제 버전·설정·기록과 함께 확인한 건이 이번 자료에 없다 [14][15]
- 이름에 제외 표시를 붙이는 방법의 근거가 애플 옛 보관 문서뿐이어서 지금도 같은지, 바로가기 링크가 기기 사이에서 어떻게 복원되는지 모른다 [16][12]
- Obsidian Git 쪽이 iCloud 병용을 공식 경고하는지 원문으로 못 봤고, 다른 동기화 서비스용 선택지가 있다는 반대 신호만 보인다 [7][17][8]
