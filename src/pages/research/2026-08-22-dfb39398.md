# 같은 프롬프트로 LLM에게 판정을 맡기면 시간·세션이 달라져도 같은 결론이 나오는가

> **한 줄 결론**
> **조건부** — 판정 모델을 날짜 붙은 한 버전으로 못 박고 결론만 비교하면 같은 결론이 나온다 [1][2]. 버전이 갈리면 답하는 버릇이 뒤집히고 [3], 흔들림을 줄이던 설정을 안 받는 모델도 있다 [4]. — 확신도 **중간** (재확인 통과 29/40 · 비판자: 방향성 결론('동일 프롬프트라도 판정은 재현되지 않으며 temperature=0으로도 제거되지 않는다')은 서로 독립적인 다수 출처가 같은 방향을 가리켜 견고하다.)

## 1. 요약

- 흔들림의 주된 원인은 운이 아니라 서버가 요청을 묶는 방식이고, 묶음에 영향받지 않게 고치면 반복이 전부 같아졌다 [1].
- 서버에 '세션' 구분은 없어 새 창도 같은 요청이다 [2][5]. 새 대화로 세 번 물은 연구에서 95~99.5%가 같은 답이었다 [6].
- 같은 이름의 모델도 속을 갈아끼우면 결론이 바뀌니, 재현의 단위는 이름이 아니라 날짜 붙은 버전이다 [3].

## 4. 엇갈리는 점

- 반대편은 글자 동일성이 요구 조건이 아니라고 본다 — 결론과 후속 조치가 같으면 실패가 아니고 사람끼리도 100% 일치하지 않는다 [8][9].
- 비판자는 사람과 기계의 일치도를 나란히 놓는 것을 짚었다 — '사람끼리의 일치'와 '같은 평가자의 두 번 일치'는 다른 것을 잰다 [10].
- 선호가 엇갈린 13.6%를 '한 번 오류율'로 바꿔 다수결 효과를 계산하면 틀린다는 지적이 남고, 흔들림을 끈 판정이 사람과 덜 맞는다는 보고도 있다 [11][7].

## 5. 아직 모르는 것

- 같은 버전에 같은 요청을 여러 달 반복해 일치율을 낸 1차 연구가 없다 — 확인된 건 버전 간 비교뿐이다 [3].
- 결론은 99% 넘게 같아도 근거 문장은 19%까지 떨어진다는 보고가 있으나, 어디까지 달라도 되는지 기준이 없다 [12].
- 흔들림을 원인별(묶음·하드웨어·조용한 업데이트)로 갈라 잰 자료가 없다 — 하드웨어를 바꿔 얻은 최대 9%포인트 차이는 같은 환경 반복이 아니다 [13].
